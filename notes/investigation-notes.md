# Investigation Notes — DNS-Based Threat Hunting

## Investigation Summary

This investigation examined DNS activity from the Windows endpoint using Elastic Security.

The goal was to identify frequently queried domains, determine which processes generated DNS requests, and attempt to correlate DNS activity with network connections.

The investigation produced useful DNS telemetry but did not establish malicious DNS behavior.

## Phase 1 — DNS Telemetry Discovery

The initial query was:

```esql
FROM logs-*
| WHERE dns.question.name IS NOT NULL
| STATS query_count = COUNT() BY dns.question.name
| SORT query_count DESC
```

Elastic processed:

```text
123 documents
51 groups
```

This confirmed that DNS telemetry was available and sufficiently populated for threat hunting.

## Frequently Queried Domains

Observed domains included:

```text
settings-win.data.microsoft.com
harmonydl.adobe.com
wpad
aka.ms
download.windowsupdate.com
```

These domains provide an important baseline because they demonstrate that the endpoint generates DNS requests for normal operating-system and application functions.

A high query count alone was therefore not considered evidence of malicious activity.

## Phase 2 — Detailed DNS Events

The following query was used:

```esql
FROM logs-*
| WHERE dns.question.name IS NOT NULL
| KEEP @timestamp, host.name, user.name, process.name, process.pid, dns.question.name
| SORT @timestamp DESC
```

Elastic returned:

```text
72 documents
```

The results provided:

```text
Timestamp
Host
User
Process
PID
DNS query
```

This allowed individual DNS events to be investigated rather than relying only on aggregate query counts.

## Process Correlation

One observed domain was:

```text
dc.services.visualstudio.com
```

The domain appeared in activity generated by:

```text
pwsh.exe
PID: 6444
User: Dell
```

and:

```text
mc-fw-host.exe
PID: 5712
User: SYSTEM
```

The important observation is that the same domain can be queried by multiple processes.

Therefore:

```text
Domain alone
```

is not sufficient to determine whether activity is suspicious.

The investigation should consider:

```text
Domain
+
Process
+
User
+
PID
+
Timestamp
```

## PowerShell DNS Activity

The `pwsh.exe` event was associated with:

```text
User: Dell
PID: 6444
Domain: dc.services.visualstudio.com
```

The presence of PowerShell is a useful hunting signal because PowerShell can be used by both legitimate administrators and attackers.

However:

```text
PowerShell DNS query
```

does not by itself prove malicious behavior.

Additional command-line and process context would be required.

## SYSTEM DNS Activity

The same domain was also associated with:

```text
Process: mc-fw-host.exe
PID: 5712
User: SYSTEM
```

This demonstrates why user context is important.

A DNS query generated by a SYSTEM process should be interpreted differently from an interactive user-generated query, but neither should automatically be considered malicious.

## Phase 3 — Network Correlation

An IP address was investigated:

```text
172.217.24.14
```

The following query was executed:

```esql
FROM logs-*
| WHERE destination.address == "172.217.24.14"
| KEEP @timestamp, host.name, user.name, process.name, process.pid, destination.address, destination.port, network.transport
| SORT @timestamp DESC
```

Result:

```text
0 documents processed
```

Elastic returned:

```text
No results match your search criteria
```

## Interpretation of the Zero Result

The lack of a network event does not establish that:

```text
No connection occurred
```

It only establishes that:

```text
No matching network telemetry was returned
within the selected search conditions.
```

Potential reasons include:

- The endpoint resolved the domain to multiple IP addresses.
- Another resolved address was used.
- The connection occurred outside the selected time range.
- Network telemetry for the connection was not collected.
- The destination was not present in the available network dataset.
- The selected IP did not correspond to the specific DNS event being investigated.

No assumptions were made to fill this evidence gap.

## Evidence Correlation

The investigation produced the following evidence chain:

```text
DNS Query
    |
    +-- dc.services.visualstudio.com
            |
            +-- pwsh.exe
            |      |
            |      +-- Dell
            |
            +-- mc-fw-host.exe
                   |
                   +-- SYSTEM
```

A direct network connection to:

```text
172.217.24.14
```

was not confirmed.

## Threat Hunting Assessment

### Confirmed

- DNS telemetry was available.
- 123 DNS documents were processed by the frequency query.
- 51 DNS groups were identified.
- Normal Microsoft, Adobe, and Windows Update-related domains were observed.
- `dc.services.visualstudio.com` was observed in DNS telemetry.
- `pwsh.exe` generated a DNS query for the domain.
- `mc-fw-host.exe` also generated a DNS query for the domain.
- No network event matching `172.217.24.14` was returned in the selected search.

### Observed

```text
Repeated DNS activity
Multiple processes querying the same domain
Normal application and operating-system domains
```

### Not Demonstrated

```text
DNS tunneling
DNS-based command-and-control
DGA activity
Malware execution
Data exfiltration
Compromise
```

## Analyst Conclusion

The available evidence supports a conclusion of **DNS activity requiring contextual analysis**, not confirmed malicious DNS behavior.

The most valuable lesson from the investigation was the importance of combining DNS data with process and network telemetry.

The investigation followed the evidence rather than assuming that a frequent, unfamiliar, or PowerShell-generated DNS query was malicious.
